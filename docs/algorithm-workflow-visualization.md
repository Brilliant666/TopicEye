# 算法可视化流程编排待办

## 结论

可行，但建议作为一个独立阶段推进。现有评分、信源权重、反馈校准和内容分析逻辑已经分散在后端服务里，直接把代码逻辑改成拖拽流程风险较高。更稳的路径是先做“可视化只读解释”，再开放少量可控参数，最后再做可拖拽编排。

## 推荐分阶段

### Phase 1: 算法解释面板

- 展示一条内容从「信源采集 → 去重 → 分类 → LLM 分析 → 评分 → 精选」的链路。
- 每个节点显示输入、输出、耗时、失败原因和关键分数。
- 不改变线上算法，只用于定位问题和收集优化反馈。

### Phase 2: 参数化调优

- 将可控参数抽出来：信源权重、时间衰减、反馈加权、精选阈值、分类白名单。
- 前端用表单和滑杆调参，后端保存版本。
- 提供“试算”能力：用最近 N 条内容模拟新参数影响。

### Phase 3: 拖拽流程编排

- 使用 React Flow 一类节点编辑器做流程画布。
- 支持节点类型：Filter、Score、LLM Analyze、Feedback Boost、Deduplicate、Route。
- 每次发布生成一个 `workflow_version`，后端执行固定 DSL，不直接执行前端拼出的任意代码。

## 技术建议

- 前端：`@xyflow/react` 作为画布，配合现有 Next.js 页面。
- 后端：定义 JSON DSL，例如 `nodes`、`edges`、`params`、`version`。
- 执行层：先做解释器，不做动态 Python 代码执行。
- 安全边界：只允许白名单节点和白名单参数，发布前必须跑试算。

## 最小可交付

先新增一个「算法实验室」页面：

- 左侧显示当前流程节点。
- 右侧显示一条内容的评分明细。
- 底部提供反馈入口：标记“推荐过高 / 推荐过低 / 分类错误 / 信源质量问题”。
- 暂不允许拖拽改流程，只记录优化建议和试算结果。
